# 图片炸开编辑器 · Image Explode Editor

把一张**已经做好的图片**（信息图、海报、截图、封面、照片）重新拆成可编辑的图层：
文字变成真正能改的文字，色块变成能换颜色的形状，图标和图像区域变成能挪能换的元素。
改完点「保存图片」，导出原分辨率成品。

**最关键的一条**：没动过的地方与原图**逐像素完全一致**。不是"看起来差不多"，是导出后
逐像素比对差异为 0。只有你真正改过的那几个元素才会被重新绘制。

![效果对比](../explode_demo_compare.png)

上图三段分别是：原图 / 改了 3 段文字 + 挪了 1 个图标 / 差异热区（红色是变化的像素，
只占全图 4.14%，形状正好贴着改过的字与图标，其余分毫未动）。

## 怎么用

1. **上传**：拖图片到中间区域，或点「选择图片」。也可以点「用示例图试试」。
2. **炸开**：弹窗里选分割强度（保守 / 标准 / 激进）与 OCR 引擎，点「开始炸开」。
   拆得不理想就换个强度点「重新炸开」，原图永远不会被改动。
3. **编辑**：
   - 左侧是图层列表，可搜索文字、按类型筛选、拖动改叠放次序、点眼睛隐藏、点锁锁定。
   - 画布上单击选中，双击文字进入原地编辑，拖动移动，八个把手缩放，顶部把手旋转。
   - 右侧属性面板改文字内容 / 字体 / 字号 / 颜色 / 字重 / 对齐 / 字距，形状改填充与圆角，
     图像可以整张替换、加滤镜、调透明度。
   - 方向键微调 1px，按住 Shift 一次 10px。`⌘Z` 撤销、`⇧⌘Z` 重做。
   - 工具栏「抠取」框选一块让后端抠成新图层；「擦除」框选一块直接擦掉。
   - 按住「对比原图」按钮可随时和原图对照。
4. **下载**：点「⤓ 下载图片」，选 PNG / JPG / WEBP、1× 或 2× 倍率，文件存到你电脑的「下载」
   文件夹。点「存工程」把当前所有图层存下来，下次用同一链接继续编辑。

## 为什么能做到"不编辑就不失真"

难点在于：要想改一行字，就得先把原来那行字从背景上擦掉，而擦除必然要靠算法猜测被
遮住的背景长什么样——猜出来的东西不可能和原图一模一样。常见做法是整张图重新合成一遍，
结果没改的地方也全被"重画"了一遍，放大看处处是薄雾。

这里用的是**双模式图层 + 按需擦除**：

- **底图始终是原图本身**。炸开后画布先把原图整张画上去，所以刚炸开时画面就是原图。
- **没动过的图层根本不重画**。它们的样子已经在底图里了，一笔都不用补。
- **只有动过的图层才打补丁**：把它原来占的那块从底图上擦掉，再在新位置画新样子。
- **擦除是按需现算的**。挪走一个压在侧栏面板上的图标时，后端只擦这一个图标，缺口由
  四周的面板像素补上，面板完好如初；如果用"把所有元素都擦掉"的预生成底图，那块会
  变成页面背景色，面板上破一个洞，还得把面板和面板上的东西全部重画一遍。
- **文字走字形掩码**，只擦笔画不动周围背景，所以改一行字连它坐着的横幅都不用重画。

界面右下角实时显示「已改 N 层 · 重绘 M 层」。实测改一段文字 M=1，挪一个元素 M=1~6，
其余 40 多层一动不动。

## 技术实现

### 后端（Python + FastAPI）

| 模块 | 做什么 |
|---|---|
| `ocr_engines.py` | 文字检测识别。优先 macOS 原生 Vision（含字符级框），跨平台兜底 RapidOCR；多尺度检测 + 去重，小字也能捞出来 |
| `style_infer.py` | 从像素反推样式：前景/背景色（线性解混出软 alpha）、字号（墨迹高度 + 字符宽度双路交叉验证）、字重、衬线、倾斜、字距、基线、对齐 |
| `segmenter.py` | 非文字元素分割：矩形 / 圆角矩形 / 椭圆 / 直线 / 图标 / 图像区域，颜色量化 + 边缘 + 轮廓分类，渐变条带自动合并，碎片合并 + 背景裁片剔除 + 发丝细条剔除 |
| `inpainter.py` | 背景擦除，按背景复杂度四级降级：纯色直填 → 平面渐变拟合 → 调和插值（∇²u=0）→ cv2.inpaint |
| `exploder.py` | 总编排：出 `layout.json` + 底图 + 两张预生成干净底图 + 每个图层的 PNG 切片 |
| `server.py` | HTTP 接口：上传 / 炸开 / 抠取 / 擦除 / 保存图片 / 存取工程 |

**字重推断**为什么不用绝对阈值：笔画粗细的测量值会被抗锯齿系统性带偏，小字受影响更大，
用固定阈值判会出现"一张图里最粗的大标题反而被判成最细"。这里改成三步：用**覆盖率积分**
量出亚像素笔画宽度（数整数像素会跳档，同样粗细的两行小字会一个算 2px 一个算 3px，
字重就跟着乱跳）、取横向纵向段长的较小值再取中位数（避开笔画交叉糊成的团）、最后在
**文档内部做相对判定**（同一张图里"谁比谁粗"是稳定可比的）。

**只炸主要素**：颜色量化和边缘检测会在同一片平滑背景里切出七八个互相穿插的大矩形，
它们墨迹几乎不重叠（交集只占较小者的 6%~10%），普通的去重规则抓不到，可每一个单独拿出来
都毫无意义——选不中、拖不动、删了也看不出区别。三道过滤依次收口：**碎片合并**（同一物体的
稀疏碎片按掩码重叠度并成一个）、**背景裁片剔除**（内部梯度只有全图均值的 0.06~0.23 倍的
判为背景切片，而真实图表曲线是 7.9 倍、照片主体 5.4 倍，中间有一个数量级的空隙）、
**发丝细条剔除**（短边不足十几像素的分隔线，它的掩码几乎填满包围盒，切片里 85% 是周围的
背景色，一旦有元素挪到它下面就会拿这片不属于自己的暗色糊上去）。真实信息图上元素数从
25 个收到 11 个，删掉的部分完整留在底图里，画面不受影响。

**擦除不留字形残影**：纯色与平面渐变两档原先只写硬掩码内部，字形外围那圈 alpha 不到一半的
抗锯齿像素原样留下。深底亮字的场合这圈恰恰是亮的，擦完提亮五倍还能清清楚楚读出原来的字。
改成按羽化半径 3 像素加权写入后，残影的高频结构强度从 0.98 降到 0.19。

**调和插值**这一档是为"平滑但不是平面"的背景加的：光晕、径向渐变、圆角卡片。
`cv2.inpaint` 从边界往里推进，两股锋面在中间相遇会留下一道暗痕——擦掉圆形图标后
那圈暗环就是它。调和插值没有锋面，边界值又精确等于四周真实像素，所以既不留环也不留
方块接缝，代价是编不出纹理，所以纹理强的地方仍然交给 `cv2.inpaint`。

### 前端（原生 JS + Canvas，无框架）

| 模块 | 做什么 |
|---|---|
| `state.js` | 文档模型与撤销重做栈，图层序列化 |
| `fontmatch.js` | 字体标定：把候选系统字体逐个渲染出来，和原图笔画做字形比对，定下字体族与字重 |
| `render.js` | 渲染引擎：重绘集合推导、补丁、双模式图层绘制、矢量文字排版（自动字号拟合）、选择框覆盖层 |
| `interact.js` | 选中 / 框选 / 拖动 / 缩放 / 旋转 / 平移 / 原地改字 / 吸附对齐 / 快捷键 |
| `panels.js` | 左侧图层面板、右侧属性面板 |
| `main.js` | 装配、上传炸开、字体标定、按需擦除底图、导出与工程存取 |

**改字后与原字一致**靠的是在浏览器里做字形比对，而不是在后端猜字体文件。候选字体逐个渲染成
掩码，与原图笔画算软 IoU、宽高比与墨迹占比，取最像的一档。几处关键取舍：

- **可用性按渲染指纹判，不能比字宽**。中日韩字符在所有中文字体里都是全角方块，字宽恒等于
  字号——十一个候选量出来一模一样（6 字 × 72px = 432.0，无一例外），比字宽会把装好的字体
  全判成"没装"。改成真渲染一遍取像素指纹。
- **逐层结论要向全篇看齐**。四位数的年份标签在各候选间分差只有 0.004 这个量级，纯属噪声，
  照着噪声走会把原图里一模一样的几个标签判成六种字体。所以先按墨迹面积和领先幅度投票选出
  全篇主字体，再让每层以随字数收紧的门槛决定是否自主判断——长句子的分差才是真信号
  （宋体正文能以 0.68 对 0.48 压过黑体），那种幅度理应放它自主。
- **基线按实测字形上沿定位**。原先按"墨迹上沿 + 字号"推算，中日韩字形的 em 框比实际墨迹高出
  一成多，整行往下坐 4~8 像素，改完字看着像掉了一行。改用 Canvas 的 `actualBoundingBox`
  实测，并按上沿/下沿比例落位（行首若是全角括号这类又高又瘦的字符，会把整串上沿单独顶高）。
  平均垂直偏移从 3.4 像素降到 0.4 像素。
- **字距钳位收在 0.12 字号内**。OCR 少认一个字（全角括号最常漏）时，原先 0.4 字号的钳位会把
  余下的字硬塞进原来的宽度，挤成一行互相压边的窄体。宁可宽度差几个百分点。

综合下来，全篇 24 层文字重绘后与原图笔画的平均吻合度从 0.41 提到 0.63。也试过"票数接近时
改选字面更全的家族"（冬青黑体只有常规和粗两个字面，苹方有四个，理论上更容易命中 Medium），
实测反而更差——中西文都被拽到苹方后年份标签吻合度从 0.70 掉到 0.43，整篇均值 0.62 → 0.57，
所以仍然只认逐层的像素证据。

## 已知边界

- **文字识别不到就改不了**：艺术字、竖排、极低对比度的文字 OCR 可能漏掉，这些区域会
  留在底图里（画面正常，只是不可编辑）。可以用「抠取」手动框成图层。
- **字体是"最像的系统字体"，不是原始字体文件**：标定在装了的系统字体里挑字形最接近的一档，
  原图若用了没装的字体（或本机只有它的两个字面而原图用了 Medium），只能取最近的近似。
  属性面板里列出了所有可用候选和各自的吻合度，可以手动改。
- **一行里多种颜色会统一成一种**：`CAGR 22-33%` 这样前半白后半青的一行，OCR 当成一行处理，
  改字后整行取主色。未编辑时仍是原始像素，颜色不受影响。
- **纹理背景上擦东西补不回纹理**：亮度能对齐到两个灰阶以内（肉眼看不出），但斜纹、网格这类
  细纹理是编不出来的，擦除区会比周围光滑一些（实测标准差 1.3 对 5.5）。这是所有基于填充的
  擦除算法的共同边界，平滑背景（纯色、渐变、光晕）则基本看不出来。
- **旋转文字**支持记录与还原角度，但原地编辑体验不如水平文字。

## 做一键启动踩到的三个坑（换机器时会用上）

- **`.app` 的主程序必须是 Mach-O 可执行文件**。把 shell 脚本填进 `CFBundleExecutable`
  在旧系统上能用，现在双击后 LaunchServices 一声不响什么都不做，`open` 还返回 0，
  极难查。`scripts/build_mac_app.sh` 改用 `osacompile` 生成 applet（自带官方二进制壳），
  脚本挂在它后面跑，不用编译器就能拿到合法 `.app`。顺手 ad-hoc 签一下，不签的新系统会挡。
- **`lsof -ti tcp:8770` 会把出站连接也算进去**。本机连过远程服务器的 8770 之后，
  浏览器进程一直挂着几条到 `21.91.41.143:8770` 的 CLOSED 记录，于是启动器以为本机端口被占，
  莫名换到 8771，而人还在按 8770 找页面。必须加 `-sTCP:LISTEN` 只看真正在监听的。
- **`nohup ... &` 挡不住进程组信号**。从 IDE 终端或脚本里启动时，那个会话一结束整组被收走，
  服务跟着断。改成让 python 用 `start_new_session=True` 起独立会话，关终端、关启动窗口
  都影响不到它。
